05 — App

Usage & deploy

Install the macOS app, grant permissions, connect a model endpoint, then run tasks or record a demo.

Download DMG · 0.2.4 ← Back to homepage

1. Before you start

MachineApple Silicon Mac (M1/M2/M3/M4) for the desktop app. Intel Macs cannot run the client.
SystemmacOS 13 Ventura or later
DiskAbout 2 GB free
Model serviceRequired — the app has no built-in model. See Deploy.

Download for macOS

  1. Open the DMG and drag UI-Mate.app into Applications.
  2. Launch from Applications — do not run from inside the DMG.
  3. If Allow applications from is set to App Store only, switch it to App Store & Known Developers.

2. Grant macOS permissions

Screen Recording and Accessibility are required. Use the in-app buttons — do not add the app manually in System Settings.

Permission UI label Why
Screen RecordingScreen RecordingSee the screen; record demos
AccessibilityAccessibilityClick and type; capture your demo actions
  1. Tap Open Screen Recording → Allow.
  2. Tap Open Accessibility → enable UI-Mate.
  3. Fully quit with ⌘Q and reopen so the banner clears.

3. Connect a model service

Open Settings (gear). Changes save automatically. Fill Model Configuration, then Test Connection.

FieldWhat to enter
Agent typeUI-Mate (default, for our trained models)
EndpointService URL, usually ending in /v1
ModelServed model name — must match the server exactly
API KeyLeave blank if unused
Provideropenai_compatible

No endpoint yet? Ask whoever runs the model service, or follow Deploy. For a quick dry-run only: OpenRouter + Agent type Kimi — not the project model.

4. Run a task & record a demo

First task

  1. New Conversation
  2. Describe the outcome in the input box.
  3. Press Enter. Avoid fighting the mouse; Stop / Esc to cancel.

Teach with a demo

  1. Demo Library → Record Demo, perform the flow, then Stop Recording (⌘⇧S).
  2. Process until status is Reusable.
  3. Apply (or /demo) → mode becomes demo-in-the-loop, then send the task.

The demo is guidance, not a frame replay — the live screen stays authoritative.

B

GPU 27B — vLLM service

Team / eval setup on a multi-GPU box. Example launch:

vllm serve "$MODEL_PATH" \
  --served-model-name gui-agent-27b \
  --trust-remote-code \
  --chat-template-content-format openai \
  --limit-mm-per-prompt '{"image":10,"video":0}' \
  --tensor-parallel-size 2 \
  --data-parallel-size 4 \
  --max-model-len 32768 \
  --host 0.0.0.0 --port 8080
  • --limit-mm-per-prompt image=10 must cover history screenshots.
  • App Endpoint: http://<GPU_IP>:8080/v1 · Model = served name · Agent UI-Mate.
  • Do not expose unauthenticated vLLM to the public internet.
C

Local Mac 9B — MLX 4bit

Offline on Apple Silicon. Convert, serve, then point the app at localhost.

python -m mlx_vlm.convert \
  --hf-path /path/to/9b-checkpoint \
  --mlx-path ~/models/gui-agent-9b-mlx-4bit \
  -q --q-bits 4 --q-group-size 64

KV_BITS=4 PREFILL_STEP_SIZE=1024 \
python -m mlx_vlm.server \
  --model ~/models/gui-agent-9b-mlx-4bit \
  --port 8080

Optional · MLX prefix-cache patch

Stock mlx-vlm barely hits prefix cache on multi-turn agent loads. Download the patch pack, unzip, apply — about 3× prefill and ~2× end-to-end step time.

Download patch zip 

pip install mlx-vlm==0.6.8
unzip mlx-vlm-gui-agent-cache.zip
cd mlx-vlm-gui-agent-cache && ./apply.sh

export APC_ENABLED=1
export APC_GROWING_IMAGES=1
export MLX_INLINE_IMAGE_POSITIONS=1
export MLX_VLM_PER_IMAGE_VISION_CACHE=1
export MLX_VLM_VISION_CACHE_SIZE=20
export APC_EXACT_CACHE_ENTRIES=8
export APC_EXACT_PREFIX_GUARD_TOKENS=64
  • Patch targets mlx-vlm 0.6.8; features stay off until those env vars are set when starting the server.
  • After patching you can keep more screenshots; still prefer balanced_1280. Prefer 6-bit quant when memory allows.
  • Confirm in server logs: Prefill completed shows cached_tokens > 0.
